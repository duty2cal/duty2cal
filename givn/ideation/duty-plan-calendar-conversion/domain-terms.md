## Confirmed standby/reserve meanings and windows

- Generated domain sentence: “The standby duty marked SB from 08:00 to 16:00 occupies eight hours; successive dated SB, SB, FREE, SB rows preserve each assigned window and the FREE day rather than become one continuous absence.”
- Generated reserve sentence: “The reserve duty marked RE from 09:00 to 17:00 uses the printed eight-hour window without calculating when an activation call must arrive.”
- Generated SBX sentence: “The single-day standby marked SBX replaces the current roster's cancelled flight assignment; the converter does not manufacture the old flight as an additional current duty.”
- SB and RE time windows are user-confirmed and use the source UTC Start/End columns under the existing timed-event rule. Missing required endpoints cannot be guessed or converted to all-day because an accounting field is zero.
- SBX's own window is confirmed as UTC through the single-day-window decision (Q29), like SB/RE. Missing required endpoints fail rather than use an all-day or cancelled-flight fallback.
- The expert's current examples use FRA; no universal station default is introduced. The user explicitly requires validating this domain knowledge against a later supplied duty plan even though the semantic rule is accepted now.
- The call-to-reporting lead-time distinction, activation, and check-in actions remain outside conversion. No dispatcher Actor, notice calculator, recurring standby block, or new aggregate is introduced.

## Confirmed whole-plan boundary

- Root noun: Duty-plan calendar.
- Kind: a calendar composition with a completion/export lifecycle; not the PDF, an output-file record, a conversion-request record, or a hosted service.
- Extent: the required activity representations derived from one supplied duty plan, including flight fragments and date evidence needed to establish complete activities.
- Invariant: a successful export is available only after every required source activity is accounted for and its required calendar dates/fields are resolved. An unresolved required activity prevents success; already understood activities do not become an apparently complete partial export.
- Existing requirement, not a new choice: the Frame already prohibits silent omissions and partial conversion output. This proposal names the consistency boundary enforcing that requirement in the domain model.
- User confirmation: accepted through the whole-plan consistency-boundary decision (Q9) on 2026-10-10; this authorizes topic-local vocabulary and a draft Event Storming canvas only.
- Primary command: Export duty plan, issued by the crew member. The draft canvas also shows internal completion, publication, and diagnostic commands acting for the crew member; they are subfunctions, not additional user goals.
- Lifecycle events in the draft canvas: Duty plan supplied; Duty-plan calendar completed; Duty-plan conversion rejected; Calendar export published; Calendar export publication failed; Conversion diagnostic written; Conversion diagnostic unavailable. Calendar/report preservation, numbering, and report attempts after every failure are confirmed. Diagnostic availability always refers to the current attempt, not an older retained report; saving it is not guaranteed on unwritable storage.
- Projection distinction: the `.ics` calendar export and failure diagnostic are output records; neither is an aggregate.
- Generated domain sentence: “The duty-plan calendar keeps an incomplete flight across a page break unresolved until its arrival fragment establishes the complete event; it cannot publish the other legs as a successful export while that leg is unresolved.”
- Architecture limit: this conceptual boundary does not require a database, persistent workflow, new service, or a particular code type.
- The observed activity meanings, within-trip identifiers, no-overwrite outputs, all-failure reports, snapshot identities, revision timestamps, and adjacent dates are confirmed separately. Optional conflicting descriptions remain unobserved/parked and source/release validation remains pending; the aggregate noun itself does not prove them.
